Scope: `tests/` — 23 test files, **640 tests**, ~6,650 lines.
Result of full run: **640 passed, 0 failed, 0 skipped, 0 xfailed** in 92s
(`pytest -n auto`). No test exercises code that no longer exists; the suite
is healthy overall. This audit is about redundancy, placement, and cost —
not correctness.

### Health checks (all clean)

- No `skip`/`xfail` marks anywhere; nothing silently rotting.
- No test targets removed behavior; everything maps to a live URL, model,
  or command.

  statuses, group permissions, invite validity).

**Verdict: keep the suite essentially as-is.** The actions below are
trimming and reorganization, not rescue work.

## 2. Remove

### R1. Duplicate old-inbox redirect test

- `tests/test_notifications.py::TestAccess::test_old_inbox_url_redirects_to_the_inbox`
- `tests/test_user_notifications.py::TestNotificationInboxView::test_old_inbox_url_redirects_to_the_canonical_one`

Both GET `/notifications/inbox/` and assert a 302 to `/notifications/`.
Identical assertion, identical URL. **Remove the copy in
`test_notifications.py`** (the redirect belongs to the member-facing inbox,
which `test_user_notifications.py` owns).

### R2. Test-executor command: 4 tests for a dev-only convenience command

`tests/test_checklists.py::TestCreateTestExecutorsCommand` spends 4 tests on
`create_test_executors`, a DEBUG-guarded helper for local development.
Consolidate to 2: one happy-path + idempotence test, one guard test
(`refuses without force` / `force overrides` merge naturally).

### R3. Declared-but-unused dependency: factory-boy

`pyproject.toml` declares `factory-boy>=3.3` but no test imports it — every
fixture builds model objects by hand. Remove the dependency, or adopt it
where fixture builders repeat (see C1). Default recommendation: remove.

## 3. Consolidate

### C1. Access-control boilerplate repeated in ~10 files (~40 tests)

Every feature re-implements the same trio:

- `test_anonymous_is_redirected_to_login`
- `test_member_outside_<X>_is_forbidden` (403 or 404)
- `test_superuser/staff_gets_in`

Found in: elections, nominations, service_award, notifications,
community_messages, communities, checklists (mention suggestions),
user_notifications, invites, ambassadors, sponsorships, sponsor_console.

Consolidate into a single parametrized access matrix — e.g.
`tests/test_access.py` with a `PROTECTED_URLS` table of
`(url, method, role, expected_status)` cases — for the *uniform* cases.
Keep a feature-local test only where the semantics differ (e.g.
communities' 404-not-403 for cross-community admins is worth its own test
with its own docstring). Expected reduction: ~40 tests → ~20 without losing
a single assertion.

### C2. Region-derivation logic tested twice

`test_communities.py::TestRegionDerivation` re-tests, one model wrapper at a
time, exactly what `test_regions.py::TestUserRegionDerivation` already
covers (US state narrows to census region; unrecognized state falls back to
Northern America; non-US country ignores state). The one genuinely distinct
assertion is "Community.region speaks the same taxonomy as User.region" —
which is already its own test (`test_region_matches_user_region_taxonomy`).

Replace the three mirrored tests with one parametrized test asserting
`Community.region` equals `User.region` for the same inputs, and keep
`test_regions.py` as the source of truth for the lookup table.

### C3. Sponsor console vs. sponsorship console: parallel test bodies

`test_sponsor_console.py` and `test_sponsorships.py` duplicate each other's
shape almost line for line (`TestConsoleAccess::test_console_access_by_role`,
`TestConsoleTemplates::test_site_templates_are_used`,
`TestConsoleWrites` create/delete/anonymous). The two consoles are
deliberately similar, so parametrize the shared cases over the two object
types rather than maintaining two copies. Keep object-specific tests
(sponsorships' public intake, staff-only fields) where they are.

### C4. Signup coverage split between test_auth.py and test_membership.py

`test_membership.py::TestPasswordlessSignup` and `test_auth.py` both POST
`/accounts/signup/` and assert a code email is sent / user created.
Suggested split: `test_auth.py` owns the flow (code email, resend,
existing-email-signin, username generation — already there);
`test_membership.py` keeps only page-copy and UI assertions (no password
fields on the form, login page offers a code, Discord absent). Drop
`test_signup_sends_a_code_and_creates_an_unusable_password` in favor of
`test_auth.py`'s equivalent + keep the end-to-end
`test_full_signup_then_signin_by_code` in one place only.

### C5. `TestSummit2027` pins seed data (5 tests → 2)

Four of the five tests assert the seeded summit's static field values (date
"2027-04-16", "Austin Central Library", section wording). That tests the
fixture, not behavior — a seed-data change means editing tests in lockstep.
Keep: `test_reseeding_does_not_duplicate_the_page` (idempotence) and
`test_summit_is_listed_on_the_events_page` (routability). Fold the detail
pins into one smoke test that renders the page and spot-checks a couple of
values.

## 4. Speed and placement

### S1. `test_pages.py` forces `bootstrap_site` on all 24 tests

The file overrides conftest's cheap `site` fixture with
`bootstrapped_site` (~1s setup **per test**; ~24s of serial setup for the
file, and it serializes xdist workers too). Some of that is unavoidable
(code-of-conduct page, blog seeds, foundational supporters), but the
`TestSupporterImport` command tests don't need any pages at all. Actions:

- Move `TestSupporterImport` (7 tests) into its own module using the plain
  `db` fixture.
- Add a `TestDonateBlock`-style opt-in for the remaining tests that genuinely
  need the full seed, and let simple render tests use the cheap `site` +
  explicitly-created children.

Same pattern applies to `test_ambassadors.py` (11 tests), where only
`TestApplyBlock` needs the bootstrapped home page.

### S2. Migration tests are expensive but earned

`test_ballot_anonymity.py::TestMigration0007/0008` (~2s call each plus
migration fixtures) are the slowest *calls* in the suite but guard one-way
data surgery on ballots. Keep. If they ever grow, mark them for `-n`-friendly
isolation; do not delete — they are the only tests that exercise data
migrations against populated tables.

### S3. Full-suite wall time is fine

92s with `-n auto` (640 tests) is healthy. The wins from S1/C1 compound:
they cut the per-test fixture cost, which is where nearly all suite time
lives (typical call phase is milliseconds; setup is 1s where bootstrap
runs).

## 5. Environment finding (not a test bug)

On this machine, a host Homebrew PostgreSQL is listening on
`127.0.0.1:5432` and shadows the containerized `db` service (which maps the
same port). `mise run test` therefore points at the *host* Postgres, where
database creation for `test_bpd` fails ("being accessed by other users")
and ~565 tests error in setup before any assertion runs. Fix options:

- `brew services stop postgresql@17` while developing, or
- move the compose mapping to `127.0.0.1:5433` and update `DATABASE_URL`
  in `mise.toml`'s `test` task.

Worth a follow-up issue so the next contributor doesn't lose an hour to it.
